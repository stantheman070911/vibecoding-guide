# Vibecoding Guide

Practical, opinionated notes for shipping real products with AI-assisted ("vibecoded") development — what stack to use, how to know a site is actually production-ready, how to close the security gaps AI coding tools tend to leave open, and how to make AI-assisted design and writing not look AI-generated.

This repo won't teach you how to prompt a model. It's the stuff that comes *after* the AI writes the code: the decisions, checklists, and taste calls that turn a working prototype into something you'd trust in front of real users and real attackers.

## Contents

1. [Stack Decision](01-stack-decision.md) — a compact, opinionated default stack for a solo founder or small team, and when it's actually worth adding more.
2. [Website Production Readiness Checklist](02-website-production-readiness-checklist.md) — everything to check before a vibecoded site goes live: mobile, SEO, forms, performance, and more.
3. [Security Remediation Playbook](03-security-remediation-playbook.md) — fixes for the most common vulnerabilities AI-generated code introduces, from exposed API keys to missing authorization checks.
4. [How to Not Look AI-Generated](04-how-to-not-look-ai-generated.md) — a designer's guide to keeping authorship and a point of view in AI-assisted design work.
5. [The Notes](05-the-notes.md) — my running personal notes and opinions. Less polished than the rest, updated as I learn.
6. [The Holy Trinity + 1](06-doc-system-templates/) — reusable CONSTITUTION/BRIEF/PLAN/LOG (+ RUNBOOK) documentation templates for keeping an AI coding agent aligned across a project's lifetime.

## Contributing

Parts 1–4 are meant to be a fairly settled reference. The notes file is where I keep looser, evolving takes — disagree with something there, or have a sharper way to say it? PRs are very welcome.
